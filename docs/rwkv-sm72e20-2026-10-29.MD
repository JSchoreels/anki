# Small model, leak-free, cool-down from epoch 20 (SM72) integration — 2026-10-29

> Superseded as the default small model on 2026-10-30 by the [cool-down from epoch 25 (profile key `sm72e25`)](rwkv-sm72e25-2026-10-30.MD). The `sm72e20` weights described here stay bundled.

The small model, leak-free, cool-down from epoch 20 (SM72) replaces the small model, leak-free, cool-down from epoch 15 (SM72, [integration report](rwkv-sm72-2026-10-28.MD)) as the default small model. To keep the two apart, the new weights have the profile key `sm72e20` and the folder `qt/aqt/rwkv_inference/sm72e20/`; the earlier cool-down keeps `sm72`. Deck Options → RWKV → Advanced → **Use Smaller Model** selects `sm72e20` when on and the Legacy big model when off. New profiles and profiles without a supported saved choice default to `sm72e20`. Existing explicit selections continue to load; a successful ordinary Deck Options save upgrades SM40, SM36, SM55, SM56 or `sm72` to `sm72e20`. Discard, a failed save and parameter-only optimization preserve the saved selection. Reopen the profile to apply a saved change. Storage precision and f32 computation are unchanged.

A new key (instead of replacing the weights under `sm72`) is deliberate: cached RWKV state is tied to the model identity, so a profile that was saved with the earlier weights must not silently reuse state computed with different ones.

## Why it is the default

The architecture export is byte-identical to the earlier SM72 release, so size (331,511 parameters, 8.3× fewer than the big model), state footprint (about 4.6 KB of card plus note state at INT8, against 25.7 KB for the big model), engine, state codecs and the leak-free input rule are all unchanged. Only the weights differ: the constant-LR phase is 20 epochs instead of 15. On identical leak-free inputs the new weights are better than the earlier cool-down on both heads, with an interval clear of zero on all three held-out sets.

Held-out users are disjoint from all training users.

## Leak-free input rule

Unchanged from the [earlier SM72 integration](rwkv-sm72-2026-10-28.MD#leak-free-input-rule): inputs 13, 14 and 15 are forced to zero on every row whenever either leak-free model is selected (`ModelKind::leak_free_inputs` is true for `sm72` and `sm72e20`), in the per-review, bulk-replay, scalar-query and batched-query paths. Other models, Legacy included, keep their feature path unchanged. The release's nearest-card rule for deleted cards never applies in the fork, because canonical history excludes deleted cards' reviews.

## Verification

The RWKV module tests were compiled and run on Windows x86-64 (CPU only) in a standalone Cargo harness that includes a copy of `rslib/src/rwkv/` and provides stand-ins for the crate items it imports (`CardType`, `relative_overdueness`, and a stub for the FSRS-dependent workload comparison, which these tests do not exercise); the full desktop build was not available on that machine.

- Default features (small primary engine): 183 passed, 30 ignored, 4 failed. Without default features (Legacy primary engine): 183 passed, 29 ignored, 4 failed.
- The four failures are the bit-exactness checks of the experimental fused packed INT4 kernels (`fused_packed::tests`, in both engines). They fail identically before this change, are test-only benchmark code, and are unrelated to it.
- New tests: `rwkv_sm72e20_matches_published_vectors` and `rwkv_sm72e20_ignores_missing_id_flags_in_every_inference_path`. `rwkv_sm72_ignores_missing_id_flags_in_every_inference_path` now shares a helper with it, `rwkv_runtime_feeds_only_sm72_leak_free_inputs` also covers `sm72e20` and still shows that SM56 is untouched, and `rwkv_runtime_restores_each_model_at_each_precision` and `rwkv_sm40_spec_matches_compiled_architecture` include the new model.
- Desktop and browser tests were updated in the existing style (model defaults, save migration, bundled file paths, embedded backend configuration) but could not be run on this machine (no pytest or Node there); the remote CI runs them. The model-key module `aqt.rwkv_model` was loaded directly: the default and the bundled file for every key resolve.
- `rustfmt --edition 2021` reports no changes for the edited Rust sources.

## Not done

- No matched backup or own-collection comparison for these weights; the release did not measure the own collection either.
- INT8 card/note state has no golden vectors upstream; the desktop's default mixed INT4-card/INT8-note storage is covered by the native restore test but not by accuracy vectors.
- The desktop feature builder's entity codes and calendar phases differ from the training scorer's; the effect on accuracy was not measured upstream.
