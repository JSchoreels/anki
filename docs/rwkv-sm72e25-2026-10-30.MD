# Small model, leak-free, cool-down from epoch 25 (SM72) integration — 2026-10-30

The small model, leak-free, cool-down from epoch 25 (SM72) replaces the small model, leak-free, cool-down from epoch 20 (SM72, [integration report](rwkv-sm72e20-2026-10-29.MD)) as the default small model. To keep the cool-downs apart, the new weights have the profile key `sm72e25` and the folder `qt/aqt/rwkv_inference/sm72e25/`; the earlier cool-downs keep `sm72e20` (from epoch 20) and `sm72` (from epoch 15), both still bundled. Deck Options → RWKV → Advanced → **Use Smaller Model** selects `sm72e25` when on and the Legacy big model when off. New profiles and profiles without a supported saved choice default to `sm72e25`. Existing explicit selections continue to load; a successful ordinary Deck Options save upgrades SM40, SM36, SM55, SM56, `sm72` or `sm72e20` to `sm72e25`. Discard, a failed save and parameter-only optimization preserve the saved selection. Reopen the profile to apply a saved change. Storage precision and f32 computation are unchanged.

A new key (instead of replacing the weights under `sm72e20`) is deliberate: cached RWKV state is tied to the model identity, so a profile that was saved with the earlier weights must not silently reuse state computed with different ones.

## Why it is the default

The architecture export is byte-identical to the earlier SM72 releases, so size (331,511 parameters, 8.3× fewer than the big model), state footprint (about 4.6 KB of card plus note state at INT8, against 25.7 KB for the big model), engine, state codecs and the leak-free input rule are all unchanged. Only the weights differ: the constant-LR phase is 25 epochs instead of 20. On identical leak-free inputs the new weights are better than the cool-down from epoch 20 on Instant with an interval clear of zero on all three held-out sets, and better on Curve in the point estimate on all three sets (interval clear of zero on the 464-user set).

Training: from scratch on all 8,000 final-tier users (581.9M reviews per epoch), 25 constant-LR AdamW epochs (7e−4, 2,048 × 16 strided lanes, carried state), then a one-epoch 32k Muon cool-down from epoch 25 over the same users (one run), with distillation from replay targets of the big model (1 leak-free epoch). Held-out users are disjoint from all training users.

## Leak-free input rule

Unchanged from the [earlier SM72 integration](rwkv-sm72-2026-10-28.MD#leak-free-input-rule): inputs 13, 14 and 15 are forced to zero on every row whenever any leak-free model is selected (`ModelKind::leak_free_inputs` is true for `sm72`, `sm72e20` and `sm72e25`), in the per-review, bulk-replay, scalar-query and batched-query paths. Other models, Legacy included, keep their feature path unchanged. The release's nearest-card rule for deleted cards never applies in the fork, because canonical history excludes deleted cards' reviews.

## Verification

The RWKV module tests were compiled and run on Windows x86-64 (CPU only, GNU toolchain) in a standalone Cargo harness that includes a copy of `rslib/src/rwkv/` and `rslib/io/`, a small stand-in for the two generated protobuf items the module imports, and stand-ins for the crate items it imports (`CardType`, `relative_overdueness`, `normalized_fsrs_parameters`); the full desktop build (protoc, ninja, a C compiler) was not available on that machine. SQLite is linked dynamically instead of bundled.

Each of the module's 243 tests (242 without default features) was run in its own process:

- Default features (small primary engine): 197 passed, 30 ignored, 16 not passing. Without default features (Legacy primary engine): 197 passed, 29 ignored, 16 not passing.
- Four of them are the bit-exactness checks of the experimental fused packed INT4 kernels (`fused_packed::tests`, in both engines), the same four that failed before the cool-down from epoch 20 integration; they are test-only benchmark code.
- The other twelve (six per engine: the two `collection_benchmark` deck-config readers, `delta_state_store_restores_checkpoint_chain`, `state_delta_chunk_reader_seeks_across_chunks`, `full_state_checkpoint_bounds_sqlite_memory` and `rwkv_state_precision_session_checkpoints_and_spills_preserve_continuation`) open SQLite and crash or fail only in this harness, which links the system `sqlite3.dll` instead of the bundled SQLite. All sixteen fail identically with the unchanged sources of the parent commit in the same harness, so none is caused by this change. The remote CI runs them with the bundled SQLite.

- New tests: `rwkv_sm72e25_matches_published_vectors` and `rwkv_sm72e25_ignores_missing_id_flags_in_every_inference_path`. `rwkv_runtime_feeds_only_sm72_leak_free_inputs` also covers `sm72e25` and still shows that SM56 is untouched, and `rwkv_runtime_restores_each_model_at_each_precision` and `rwkv_sm40_spec_matches_compiled_architecture` include the new model.
- Desktop and browser tests were updated in the existing style (model defaults, save migration from `sm72e20` too, bundled file paths, embedded backend configuration) but could not be run on this machine (no pytest, PyQt or Node there); the remote CI runs them. The model-key module `aqt.rwkv_model` was loaded directly: the default and the bundled file for every key resolve.
- `rustfmt --edition 2021 --check` reports no changes for the edited Rust sources.

## Not done

- No matched backup or own-collection comparison for these weights; the package did not measure the own collection either.
- INT4 card state was not scored upstream for these weights (the cool-down from epoch 20 lost +0.000039 Curve / +0.000051 Instant at INT4 cards against INT8 state on the 732-user set). INT8 card/note state has no golden vectors upstream; the desktop's default mixed INT4-card/INT8-note storage is covered by the native restore test but not by accuracy vectors.
- The desktop feature builder's entity codes and calendar phases differ from the training scorer's; the effect on accuracy was not measured upstream.
