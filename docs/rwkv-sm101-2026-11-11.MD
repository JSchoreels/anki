# Model sizes Big / Small / Tiny and the smaller instant-only model (SM101): integration — 2026-11-11

Deck Options → RWKV → Advanced replaces the **Use Smaller Model** switch with three model sizes for the whole local profile: **Big**, **Small** (the default) and **Tiny**. Big and Small are exactly the two former choices; Tiny is new. Tiny is Small with the smaller instant-only model (SM101) in the place of the show-time instant-only model, stage 2 (SM98): it only shrinks RWKV-Instant's state, and RWKV-Curve, its intervals, S90, the workload simulation and the answer-time estimate stay on the default small model (SM63), exactly as with Small.

## What each size runs

Read once per profile open from the size, the schedulers the presets use and the one-model opt-out (`aqt.rwkv_model.runtime_models`). A preset uses RWKV-Curve when RWKV-Curve is its scheduler or RWKV-Instant's **Fallback : Due-Date Calculator**.

| Presets use | Big (`legacy`) | Small (`sm72e25`, default) | Tiny (`tiny`) |
| --- | --- | --- | --- |
| RWKV-Instant, no RWKV-Curve (opt-out ignored) | the big model (1 leak-free epoch) alone | the show-time instant-only model, stage 2 (SM98) alone, `InstantOnly` | the smaller instant-only model (SM101) alone, `InstantOnly` |
| both, opt-out off (default) | the big model alone | pair: RWKV-Instant from SM98, curve from the default small model (SM63) | pair: RWKV-Instant from SM101, curve from the default small model (SM63) |
| both, opt-out on | the big model alone | the default small model (SM63) alone | the default small model (SM63) alone |
| RWKV-Curve only, or neither | the big model alone | the default small model (SM63) alone | the default small model (SM63) alone |

Without RWKV-Curve, the instant model alone has no curve: due dates and memory states come from the FSRS fallback and the RWKV workload simulation is unavailable, as for Small since 2026-11-10 ([SM98 integration](rwkv-sm98-2026-11-10.MD)). A custom `ANKI_RWKV_MODEL_PATH` replaces the size's full model (Tiny's is the default small model) and serves both schedulers.

## Profile values and migration

The size is stored in the existing profile key `rwkvModel`; Big and Small keep the values earlier builds stored, so no profile is rewritten:

- `legacy` → Big, `sm72e25` → Small, `tiny` → Tiny (new). New profiles store `sm72e25`; missing or unknown values (including the model keys `sm57`, `sm98` and `sm101`, which are never profile values) resolve to Small. An earlier build reads `tiny` as unknown and falls back to Small.
- The older small models `sm40`, `sm36`, `sm55`, `sm56`, `sm72` and `sm72e20` keep their former handling: they still run alone until the next ordinary Deck Options save, which stores Small; Deck Options shows them as Small. Mapping them to Small at once would rebuild state on a version update without the user touching anything; the save-time switch was already the documented path.
- `sm92`, the show-time retrain of the release (SM92), stays a preserved advanced value (the user's 2026-11-05 decision: SM92 an option only). Deck Options lists it as a fourth choice, with a note, only for a profile that already holds it; picking a size removes it from the list.

Changing the size takes effect at the next profile open and rebuilds RWKV state where the runtime changes: the replay key holds the runtime's `model` and, for a pair, its `instantModel`, so the SM101 pair (`sm72e25` + `sm101`) and SM101 alone (`sm101`) have keys of their own, distinct from Small's (`sm72e25` + `sm98`, `sm98`) and from every other layout; the model cache key also hashes the main model's weights file. Small and Tiny without RWKV-Instant run the same model (the default small model alone), so switching between them there keeps the state.

## Engine: one small engine, a per-model layer plan

The smaller instant-only model (SM101) is the small architecture with one card layer instead of two (`w64-c1`: card/deck/note/preset/user depths 1/4/1/3/3, the 13 interleaved layer steps without card layer 1, 12 steps; every width, head and LoRA is the small model's, and the remaining card layer keeps its channel mixer). The engine dimensions are compile-time constants; instead of compiling a third specialization, the small engine reads the card layers from the weights:

- `architecture.rs`: `LayerPlan { module_layers, steps }`, `ENGINE_LAYER_PLAN` (the engine's `MODULE_LAYERS` / `LAYER_STEPS`) and `TINY_LAYER_PLAN` (`TINY_MODULE_LAYERS`, `TINY_LAYER_STEPS`).
- `SrsModel::from_weights` picks the tiny plan in the small engine when the weights hold no `rwkv_modules.0.blocks.1.` tensor at all, and stores it on the model; the five layer-step loops (warm-up and replay, queue scoring, batched queries, answer-time inputs, bulk replay) iterate `self.layer_plan.steps` instead of the constant. Tensor loops, kernels and state codecs are unchanged: the state already carried its layer count. A compile-time assert keeps the tiny plan's layer rounds equal to the answer-time head's.
- `ModelKind::Sm101` (`sm101`): leak-free and instant-only like SM98; `RwkvRuntime` checks the weights' card layers against the key (`sm101`: 1, every other small key: 2) and refuses a mismatch, alone or in a pair. `load_paired` accepts SM101 only as the instant side beside a full leak-free release.

## Speed: Small unchanged, Tiny faster

Manual benchmark `rwkv_model_size_benchmark` (`rslib/src/rwkv/model_size_bench.rs`, run in the native harness on Windows, Ryzen 7 9850X3D, while a GPU training job ran on the same machine): a synthetic history of 4,000 cards, 2,000 notes and 32,000 answers, int4 cards + int8 notes; per process one untimed and five timed samples, median; three processes per runtime and tree, interleaved with the same benchmark file on `origin/main` (`cea5304b9`). Reviews/s = answers replayed per second of `warm_up_reviews`; CPU = the whole process's CPU time (loads, six samples, queue scoring and full predictions). Every prediction checksum is identical between the trees.

| Runtime (8 threads, default pool) | `origin/main` reviews/s | this change | CPU s main → change | queue scoring 4,000 cards | per card + note |
| --- | --- | --- | --- | --- | --- |
| Small, curve only: the default small model (SM63) alone | 45,378 | 45,776 (+0.9%) | 58.8 → 59.4 | 80 → 79 ms | 3,530 B |

| Small, RWKV-Instant only: SM98 alone | 46,469 | 46,416 (−0.1%) | 52.6 → 52.7 | 79 → 78 ms | 3,530 B |
| Tiny, both: SM63 + SM101 pair | — | 27,699 | 100.1 | 70 ms | 6,190 B |
| Tiny, RWKV-Instant only: SM101 alone | — | 49,847 | 48.1 | 71 ms | 2,622 B |
| Big | 14,950 | 14,923 (−0.2%) | 194.6 → 196.4 | 223 → 248 ms | 19,554 B |

| Runtime (1 thread) | `origin/main` reviews/s | this change | CPU s main → change |

Small's speed and CPU are unchanged within the run-to-run noise: every difference is within ±1.5%, and SM63 alone and SM98 alone, which run the identical code path with different weights, move in opposite directions (−1.3% and +1.5% on one thread), while the best warm-up of each process is the same. Tiny replays answers 7-10% faster than Small with RWKV-Instant only (SM101 alone against SM98 alone, 8 and 1 threads) and 5-6% faster with both schedulers, and scores the queue 5-10% faster, from the missing card layer.

## Accuracy

Upstream (anki-rwkv `artifacts/small-model/sm101/sm101-decision.md`; 722 users of the 732-user set, instant head, w8+s8, leak-free, paired user bootstrap 95% CI, % of the big model (1 leak-free epoch)'s normal-input instant LogLoss 0.275757; negative = better): SM101 minus SM98 on show-time inputs +0.192% [+0.171, +0.215]; minus the show-time retrain of the release (SM92) −0.057% [−0.079, −0.034]; minus the default small model (SM63) −0.362% [−0.463, −0.284]. On the 1,500 validation users, SM101 minus SM98 +0.190% [+0.171, +0.212] of SM98's LogLoss. So Tiny's RWKV-Instant is slightly less accurate than Small's, still better than the default small model's or SM92's.

## Compact state formats: accuracy cost for Tiny and Small

Measured upstream on CPU (anki-rwkv `artifacts/small-model/sm101/sm104/`): the research scorer with f32 weights, leak-free inputs, show-time inputs, the 80 random users of the 732-user set drawn for the int4 drift check (SM78), 1,019,305 benchmark reviews; each format against the same model with f32 state, instant LogLoss, % of that model's f32-state LogLoss, paired user bootstrap 2,000, seed 0, 95% CI. The scorer rounds the card and note WKV rows in the fork's formats (`int8`: int8 rows, `cards_int4_notes_int8`: int4 card rows and int8 note rows, one f32 scale per row) and keeps the token-shift vectors at f32 (the fork rounds them to f16, a far smaller rounding).

| RWKV-Instant model | f32 state LogLoss | int8 state | int4 cards + int8 notes (default) |
| --- | --- | --- | --- |
| the smaller instant-only model (SM101), Tiny | 0.294372 | −0.001% [−0.003, +0.001] | +0.013% [+0.003, +0.023] |
| the show-time instant-only model, stage 2 (SM98), Small | 0.293658 | −0.000% [−0.001, +0.000] | +0.010% [+0.001, +0.018] |
| Tiny's cost minus Small's | | −0.000% [−0.002, +0.001] | +0.003% [−0.005, +0.013] |

int8 state costs nothing measurable for either model, and the default int4-card state costs about 0.01% for both; Tiny's int4 cost is not clearly larger than Small's (the difference's interval includes 0). In the fork every state precision runs SM101: the precision, paired and instant-only tests above pass at f32, int8 and int4 cards + int8 notes, and the stored sizes are exact.
