# The instant model for RWKV-Instant (SM93): integration — 2026-11-07

RWKV-Instant can now run on its own model, the instant-only small model (SM57), while RWKV-Curve keeps the small model, leak-free, cool-down from epoch 25 (SM63, profile key `sm72e25`). The instant-only small model (SM57) is that release trained one more epoch, plus the release's exact one-epoch 32k Muon cool-down, with the curve loss switched off: only its instant / rating head (`p_imm`, `p_rating`) was trained. Its curve head is untrained, so it never provides curve recall, intervals, S90 or answer times.

## Update 2026-11-09: RWKV-Instant uses the show-time retrain of the release (SM92)

Wherever RWKV-Instant used the instant-only small model (SM57) stage 4, it now uses the show-time retrain of the release (SM92, profile key `sm92`, already bundled at `qt/aqt/rwkv_inference/sm92/`). ## Which model serves which scheduler

The choice is made once per profile open from the profile's model, the schedulers its presets use, and one Advanced toggle. Only the small model (SM63, `sm72e25`) has the instant-only sibling; the show-time retrain of the release (SM92), Legacy and the older small models serve both schedulers alone, as before.

| Presets use | Toggle **Use specialized model for RWKV-Instant (2x RAM if used alongside RWKV-Curve)** | RWKV-Instant | RWKV-Curve | Model states |
| --- | --- | --- | --- | --- |
| RWKV-Instant only | ignored | the instant-only small model (SM57) | (none) | one |
| both | off (default) | the small model (SM63) | the small model (SM63) | one |
| both | on | the instant-only small model (SM57) | the small model (SM63) | two |
| RWKV-Curve only, or neither | ignored | (none) | the small model (SM63) | one |

"Presets use RWKV-Curve" means some preset has **Use RWKV-Curve for answer intervals** on (`rwkv_review_enabled`), which includes an RWKV-Instant preset whose fallback is RWKV-Curve; "RWKV-Instant" means some preset has **Use RWKV-Instant to choose review cards** on. The toggle is stored in the profile (`rwkvSpecializedInstantModel`, default off), next to `rwkvModel` and `rwkvStatePrecision`, through the same `rwkv_profile_settings` path of Deck Options (field `specialized_instant_model`); it is shown under Advanced when the small model (SM63) is selected. Like a model change, a changed toggle or a changed set of schedulers applies at the next profile open (the session keeps its runtime, cache identity and background jobs).

What stays on the small model's (SM63) state: curve recall, intervals, S90, current interval, workload simulations and the answer-time head (SM83), which was trained on the small model's (SM63) frozen features and never receives features from another model.

**Profile with RWKV-Instant only.** RWKV-Instant itself needs nothing from the small model (SM63): queue selection, the RWKV-Instant due search, the Memorised statistic and the "R after review" previews all read the instant / rating head. With no RWKV-Curve preset, the runtime loads the instant-only model alone: one model state, the same memory as today. What it does not provide, by design: curve recall, intervals and S90 (Instant presets with an FSRS fallback keep FSRS intervals, as before; the runtime returns no RWKV intervals, so nothing falls back to an untrained curve), the RWKV workload simulation (it schedules with the curve; it reports that the instant-only model has no trained curve), and **RWKV : Answer Time by Button** / **RWKV : Expected Answer Time** in Card Info (the head would otherwise be fed features of a model it was not trained on). Keeping the small model (SM63) warm only for the answer-time display would double the state, so it is not done; a profile that wants the answer time uses the shared model by enabling RWKV-Curve on some preset.

## Runtime design

`RwkvRuntime` (`rslib/src/rwkv/runtime.rs`) gains two variants for the small engine:

- `InstantOnly`: the instant-only model alone (`ModelKind::Sm57`, leak-free inputs). Its outputs carry instant recall and button probabilities; curve recall, intervals, S90 and the current interval are `None`, there is no answer-time head, and workload simulations return an error. `review` and `predict_many` skip the four simulated answers that only intervals need (500 full predictions: 43 ms instead of 253 ms).
- `Paired` (`RwkvRuntime::load_paired`): the release engine and the instant-only engine side by side. Both replay every answer (in parallel, `rayon::join`), so their feature state, ID encodings and stream states stay in step; feature building commits nothing on queries, so a query on one engine cannot desynchronise the other. Instant-only calls (`predict_retrievability_many*`, the queue's resident scoring, replay predictions, future recall after an answer) run only the instant engine. `predict_many` and `review` take curve recall, intervals, S90 and the current interval from the release and instant recall and button probabilities from the instant engine, which computes only the query row. The answer-time head runs on the release's state; workload simulations and comparisons run on the release.

Persistence keeps one blob per entity and one store file (`paired.rs`): each serialized stream state is `ARWKVPAIRSTATE1` + the release's length + the release's state + the instant model's state; the runtime cache is `ARWKVPAIRCACHE1` + both caches. In the SQLite delta store, both models' deltas live in `segment_state_chunks` of the same segment (the instant model's chunks from index 2^32), so the desktop's pruning, compaction and renames handle them unchanged; the segment's `runtime_state` holds both runtime caches. The resident-state spill writes the instant model's file next to the release's (`stash-spill.bin.instant`). Undo states hold both feature states. Paired and single layouts reject each other (a paired store, snapshot or cache never restores into a single runtime and the reverse), and the desktop's replay key gains `instantModel` for paired runtimes, so changing the toggle rebuilds state from history once.

Python (`qt/aqt/rwkv_model.py`): `runtime_models()` implements the table above; `rwkv_scheduler._rwkv_runtime_models_for_profile()` reads the presets and the toggle when the backend is created, `begin_rwkv_state_cache_startup` reloads the backend when they changed, and `EmbeddedRwkvReviewerBackend` passes `instant_model_path` / `instant_model` to the native `RwkvInference`. A custom `ANKI_RWKV_MODEL_PATH` keeps one model.

## Memory and CPU

Measured in the native harness (4,000 cards, 2,000 notes, 32,000 answers, INT4 card / INT8 note state, one thread pool):

| Runtime | Warm-up (32,000 answers) | Queue scoring (4,000 cards) | 500 full predictions | Stream state | Runtime cache |
| --- | --- | --- | --- | --- | --- |
| The small model (SM63) alone | 914 ms | 95 ms | 253 ms | 10.6 MB (2.8 KB per card) | 0.9 MB |
| Paired: the small model (SM63) + the instant-only model (SM57) | 1,482 ms (both replay in parallel, about 2× CPU) | 93 ms | 338 ms | 21.3 MB (5.6 KB per card) | 1.8 MB |
| The instant-only model (SM57) alone | 893 ms | 92 ms | 43 ms | 10.6 MB (2.8 KB per card) | 0.9 MB |

Extra weights: 1.35 MB (f32) when paired. The second model loads only in the paired case; with one scheduler, or with both and the toggle off, nothing is duplicated.
