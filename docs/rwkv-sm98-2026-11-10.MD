# The show-time instant-only model, stage 2 (SM98) for RWKV-Instant: integration — 2026-11-10

With the default small model, leak-free, cool-down from epoch 25 (SM63, profile key `sm72e25`), every profile that uses RWKV-Instant now runs RWKV-Instant on the show-time instant-only model, stage 2 (SM98, model kind `sm98`) by default, beside the small model (SM63), which keeps RWKV-Curve, the curve recall, the intervals, S90, the workload simulation and the answer-time estimate. One Advanced opt-out, **Use one model for RWKV (about half the memory, slightly worse RWKV-Instant predictions)**, brings back the earlier single-model behaviour. Approved by the user on 2026-11-10 ("Yes let's integrate it", then the pair as the default).

The show-time instant-only model, stage 2 (SM98) is the release's weights trained further with the curve loss switched off (`curve_loss_weight` 0) and with show-time intervals (`show_time_intervals`): the show-time instant-only small model (SM96)'s instant-only epoch 31, four more constant-learning-rate instant-only epochs (32-35), then the release's one-epoch 32k Muon cool-down, all on show-time inputs. Only its instant / rating head (`p_imm`, `p_rating`) was trained. Its curve head is untrained, so it never runs alone and never provides curve recall, intervals, S90 or answer times.

## Which model serves which scheduler

Read once per profile open from the profile's model, the schedulers its presets use and the opt-out (`aqt.rwkv_model.runtime_models`):

| Presets use (model SM63, `sm72e25`) | Opt-out off (default) | Opt-out on |
| --- | --- | --- |
| RWKV-Instant only | paired: RWKV-Instant from the show-time instant-only model, stage 2 (SM98); curve, intervals, S90 and answer time from the small model (SM63); two model states | the show-time retrain of the release (SM92) alone, as for a profile whose model is `sm92`; one model state |
| both RWKV-Instant and RWKV-Curve | paired, as above; two model states | the small model (SM63) alone for both; one model state |
| RWKV-Curve only, or neither | the small model (SM63) alone | the small model (SM63) alone |

A profile whose model is the show-time retrain of the release (SM92), Legacy or an older small model is unchanged: that model serves both schedulers alone, and the opt-out does not apply. A custom `ANKI_RWKV_MODEL_PATH` keeps one model.

Before this change, the table read: RWKV-Instant only → the show-time retrain (SM92) alone; both → the small model (SM63) alone unless the opt-in toggle **Use specialized model for RWKV-Instant** was on, which paired the small model (SM63) with the show-time retrain (SM92). The opt-out's "on" column is that old default.

## Accuracy (upstream)

anki-rwkv branch `sm98`, `artifacts/small-model/sm98/sm98-result.md` and `sm98-decision.json`. Instant LogLoss on show-time inputs (the times RWKV-Instant gives the model), 722 users of the 732-user held-out set, INT8 per-channel weights and INT8 card / note state (w8+s8), leak-free inputs (deleted cards: neighbour), review-weighted, paired user bootstrap (2,000 resamples, seed 0), 95% intervals. Unit: % of the big model (1 leak-free epoch)'s normal-input instant LogLoss on the same users (0.275757); negative means the show-time instant-only model, stage 2 (SM98) is better.

On the 1,500 validation users outside the 732-user set (1,487 with a release reference), show-time inputs, unit % of the release's own LogLoss on the same users: the show-time instant-only model, stage 2 (SM98) minus the release (SM63) is **−0.512% [−0.564, −0.469]** (0.279162 against 0.2806, 1,399 users better, 88 worse).

The pre-registered rule of the experiment compared the show-time instant-only model, stage 2 (SM98) with the show-time instant-only small model (SM96) and said "no go": −0.035% is below the 0.05 minimum. The show-time instant-only small model (SM96) was never bundled, so for the fork the comparison that matters is against the show-time retrain (SM92), which RWKV-Instant used until now, and the release; both gains are clear. Its untrained curve head scores +58.6% of the release's curve LogLoss on the 1,500 validation users and is never served.

## The setting

- Label: **Use one model for RWKV (about half the memory, slightly worse RWKV-Instant predictions)**, under Advanced, shown whenever the small model (SM63) is selected, so for every profile that uses RWKV-Instant with it, alone or with RWKV-Curve (`ts/routes/deck-options/RwkvModelOptions.svelte`). Strings `deck-config-rwkv-single-model` and `deck-config-rwkv-single-model-description`; the former `deck-config-rwkv-specialized-instant-model(-description)` strings are removed.
- Stored in the profile as `rwkvSingleModel` (default off, not synced), saved with the model choice through `rwkv_profile_settings.single_model` (proto field 4).
- The former opt-in toggle `rwkvSpecializedInstantModel` (proto field 3, now `reserved`) meant the opposite. It is ignored: a profile that had it on gets the pair, as it asked; a profile that had it off (the default) gets the new default, the pair, and can opt out. The next successful Deck Options save drops the old key from the profile.

## Runtime

- `ModelKind::Sm98` (`rslib/src/rwkv/runtime.rs`): leak-free inputs and instant-only, like the instant-only small model (SM57). Loaded alone, an instant-only model always becomes the `InstantOnly` runtime (no curve, no intervals, no S90, no answer time, workload simulations refused), never a full model; the Python selection never loads the show-time instant-only model, stage 2 (SM98) alone.
- `RwkvRuntime::load_paired` accepts it as the instant side: a small model distinct from the release, with the same leak-free input rule, beside a full small release. It is rejected as the release side, beside itself, and beside Legacy or a leak-input model. No runtime code changed: the paired mode (`Paired`, `ARWKVPAIRSTATE1` states, `ARWKVPAIRCACHE1` cache, one store file) is the one of the [instant model for RWKV-Instant (SM93) integration](rwkv-sm93-2026-11-07.MD#runtime-design).
- Show-time inputs need no feature-builder change: the fork already builds the show-time intervals the model was trained on (as for the show-time retrain (SM92)); `rwkv_sm98_feature_builder_matches_show_time_intervals` checks the native feature builder against the trainer's interval inputs of all 6,543 queries and 7,860 answers of the package vectors (maximum error 7.5e−7).
- Python (`qt/aqt/rwkv_model.py`): `RWKV_SPECIALIZED_INSTANT_MODEL = "sm98"` (one constant to switch), `RWKV_INSTANT_ONLY_MODELS = ("sm57", "sm98")`, `RWKV_MODEL_FILES["sm98"]`, `single_model_for_profile`, and `runtime_models(..., single_model=...)`. The show-time retrain (SM92, `RWKV_INSTANT_MODEL`) and the instant-only small model (SM57, `RWKV_INSTANT_ONLY_MODEL`) stay bundled and selectable.

## States rebuild once

The replay key carries `instantModel`. Profiles that now run the pair (`sm72e25` + `sm98`) have a new key, so their RWKV state rebuilds from history once at the first open: profiles that used RWKV-Instant with the default single model, profiles that used RWKV-Instant only (before: the show-time retrain (SM92) alone), and profiles that had the old toggle on (before: paired with `sm92`). States of different pairs are never mixed. Turning the opt-out on or off later also rebuilds once, at the next profile open.

## Memory and CPU

Same architecture and state size as the instant-only small model (SM57), so the [SM93 measurements](rwkv-sm93-2026-11-07.MD#memory-and-cpu) hold (4,000 cards, 32,000 answers, INT4 card / INT8 note state): paired stream state 5.6 KB per card instead of 2.8 KB, warm-up 1.48 s instead of 0.91 s (both models replay in parallel, about 2× answer-replay CPU), queue scoring unchanged (93 ms against 95 ms), 1.35 MB more weights (f32). This is now the default cost of a profile that uses RWKV-Instant with the small model (SM63); the opt-out returns to one state.
