# The show-time instant-only model, stage 2 (SM98) for RWKV-Instant: integration — 2026-11-10

With the default small model, leak-free, cool-down from epoch 25 (SM63, profile key `sm72e25`), profiles that use RWKV-Instant normally run it on the show-time instant-only model, stage 2 (SM98, model kind `sm98`): alone when no preset uses RWKV-Curve (the smart switch, below), beside the small model (SM63) when presets use both, where the small model (SM63) keeps RWKV-Curve, the curve recall, the intervals, S90, the workload simulation and the answer-time estimate. One Advanced opt-out, **Use one model for RWKV**, shares the show-time retrain (SM92) when presets use both. Approved by the user on 2026-11-10 ("Yes let's integrate it", then the pair as the default, then the smart switch).

The show-time instant-only model, stage 2 (SM98) is the release's weights trained further with the curve loss switched off (`curve_loss_weight` 0) and with show-time intervals (`show_time_intervals`): the show-time instant-only small model (SM96)'s instant-only epoch 31, four more constant-learning-rate instant-only epochs (32-35), then the release's one-epoch 32k Muon cool-down, all on show-time inputs. Only its instant / rating head (`p_imm`, `p_rating`) was trained. Its curve head is untrained, so it never provides curve recall, intervals, S90 or answer times: alone it runs as the native `InstantOnly` runtime.

## Which model serves which scheduler

Read once per profile open from the profile's model, the schedulers its presets use and the opt-out (`aqt.rwkv_model.runtime_models`). A preset uses RWKV-Curve when RWKV-Curve is its scheduler or RWKV-Instant's **Fallback : Due-Date Calculator** (both set `rwkv_review_enabled`, which `_rwkv_collection_config_state(...).curve_enabled` reads):

| Presets use (model SM63, `sm72e25`) | Opt-out off (default) | Opt-out on |
| --- | --- | --- |
| RWKV-Instant, and no preset uses RWKV-Curve | the show-time instant-only model, stage 2 (SM98) alone, `InstantOnly` runtime: RWKV-Instant's recall and button probabilities only; due dates and memory states from the FSRS fallback; one model state | the same (the opt-out is ignored: it is already one model) |
| both RWKV-Instant and RWKV-Curve | paired: RWKV-Instant from the show-time instant-only model, stage 2 (SM98); curve, intervals, S90 and answer time from the small model (SM63); two model states | the show-time retrain (SM92) alone for both; one model state |
| RWKV-Curve only, or neither | the small model (SM63) alone | the small model (SM63) alone |

A profile whose model is the show-time retrain of the release (SM92), Legacy or an older small model is unchanged: that model serves both schedulers alone, and the opt-out does not apply. A custom `ANKI_RWKV_MODEL_PATH` keeps one model.

Before this change, the table read: RWKV-Instant only → the show-time retrain (SM92) alone; both → the small model (SM63) alone unless the opt-in toggle **Use specialized model for RWKV-Instant** was on, which paired the small model (SM63) with the show-time retrain (SM92). The first version of this integration paired the show-time instant-only model, stage 2 (SM98) with the small model (SM63) for RWKV-Instant only too, and the opt-out then ran the show-time retrain (SM92) alone; the smart switch replaced both the same day.

## The smart switch: RWKV-Instant without RWKV-Curve (2026-11-10)

The user's decision: "cant we do like before with a smart switch to instant only? The stability and such can be computed with FSRS if rwkv curve is not enabled", and for the workload simulator, "Simulator unavailable". As with the instant-only small model (SM57) on 2026-11-07, a profile that uses RWKV-Instant and no RWKV-Curve now runs the show-time instant-only model, stage 2 (SM98) alone: one model state instead of two (about half the state memory and answer-replay CPU of the pair), with RWKV-Instant's predictions unchanged. The show-time retrain (SM92) is also picked automatically when both schedulers use the one-model opt-out.

What the instant-only runtime gives, and what each curve-dependent path does without a curve:

- Queue order, minimum daily reviews, repeat spacing, candidate refresh, filtered decks, the stats and Browser RWKV recall (`prop:rwkv:r`), the calibration data and Card Info's RWKV recall, button probabilities and after-review rows: RWKV-Instant's recall and buttons, as in the pair (the pair already took them from the show-time instant-only model, stage 2 (SM98)).
- Scheduling and the answer buttons: no interval overrides, so the FSRS states stay (`update_reviewer_scheduling_states`), nothing writes an RWKV S90 to the card (`set_answer_rwkv_s90`), and memory states are FSRS's.
- Card Info: FSRS stability and retrievability from the card's stats; the RWKV-Curve S90 rows and the answer-time rows are omitted (native `has_answer_time_head` is false, and `rwkv_card_info_rows` also checks that the runtime has a curve).
- RWKV-Curve recall and due searches (`prop:rwkv-curve:r`, `is:rwkv-curve:due`) and their columns: no curve scores are stored, so they match nothing.
- **Reschedule with RWKV-Curve**: no prediction has an interval and S90, so no card changes.
- Workload simulation (Deck Options, **Compare RWKV with FSRS**): unavailable. The simulator asks `rwkvWorkloadAvailable` when it opens and before each run; without a curve model it shows "RWKV workload simulation needs RWKV-Curve. Turn on RWKV-Curve in a preset (as its scheduler or as RWKV-Instant's fallback) and save to simulate RWKV workload." (`deck-config-rwkv-workload-needs-curve`) and disables Simulate. `simulate_rwkv_workload`, `compare_rwkv_and_fsrs_workload` and `start_rwkv_workload_bytes` refuse with the same message (`RwkvWorkloadUnavailableError`) before loading any state, and the simulator shows it instead of a raw error. FSRS simulations are unchanged; the workload forecast logic is not touched.

Saving a preset that turns RWKV-Curve on (as scheduler or fallback) while the instant-only runtime is resident drops it (`refresh_rwkv_runtime_models_after_preset_change`, called on deck-config changes before the usual state recovery): the next use loads the pair, or the show-time retrain (SM92) alone with the opt-out, and rebuilds its state once, so RWKV-Curve never falls back to FSRS intervals until a restart. Every other change of the presets' schedulers or of the opt-out still applies at the next profile open.

The opt-out's description says it only applies when presets use both RWKV-Instant and RWKV-Curve; it is shown for Small and Tiny, since the runtime follows every preset's scheduler, not just the preset being edited.

## Accuracy (upstream)

anki-rwkv branch `sm98`, `artifacts/small-model/sm98/sm98-result.md` and `sm98-decision.json`. Instant LogLoss on show-time inputs (the times RWKV-Instant gives the model), 722 users of the 732-user held-out set, INT8 per-channel weights and INT8 card / note state (w8+s8), leak-free inputs (deleted cards: neighbour), review-weighted, paired user bootstrap (2,000 resamples, seed 0), 95% intervals. Unit: % of the big model (1 leak-free epoch)'s normal-input instant LogLoss on the same users (0.275757); negative means the show-time instant-only model, stage 2 (SM98) is better.

| The show-time instant-only model, stage 2 (SM98) minus | SM98 | Other model | % [95% CI] | Users better / worse |

On the 1,500 validation users outside the 732-user set (1,487 with a release reference), show-time inputs, unit % of the release's own LogLoss on the same users: the show-time instant-only model, stage 2 (SM98) minus the release (SM63) is **−0.512% [−0.564, −0.469]** (0.279162 against 0.2806, 1,399 users better, 88 worse).

The pre-registered rule of the experiment compared the show-time instant-only model, stage 2 (SM98) with the show-time instant-only small model (SM96) and said "no go": −0.035% is below the 0.05 minimum. The show-time instant-only small model (SM96) was never bundled, so for the fork the comparison that matters is against the show-time retrain (SM92), which RWKV-Instant used until now, and the release; both gains are clear. Its untrained curve head scores +58.6% of the release's curve LogLoss on the 1,500 validation users and is never served.

## The setting

- Label: **Use one model for RWKV**, under Advanced, shown whenever Small or Tiny is selected, whether RWKV-Instant runs alone or with RWKV-Curve (`ts/routes/deck-options/RwkvModelOptions.svelte`). Strings `deck-config-rwkv-single-model`, `deck-config-rwkv-single-model-explanation` and `deck-config-rwkv-single-model-instant-only`; the former `deck-config-rwkv-specialized-instant-model(-description)` strings are removed.
- Stored in the profile as `rwkvSingleModel` (default off, not synced), saved with the model choice through `rwkv_profile_settings.single_model` (proto field 4).
- The former opt-in toggle `rwkvSpecializedInstantModel` (proto field 3, now `reserved`) meant the opposite. It is ignored: a profile that had it on gets the pair, as it asked; a profile that had it off (the default) gets the new default, the pair, and can opt out. The next successful Deck Options save drops the old key from the profile.

## Runtime

- `ModelKind::Sm98` (`rslib/src/rwkv/runtime.rs`): leak-free inputs and instant-only, like the instant-only small model (SM57). Loaded alone, an instant-only model always becomes the `InstantOnly` runtime (no curve, no intervals, no S90, no answer time, workload simulations refused), never a full model; since the smart switch the Python selection loads the show-time instant-only model, stage 2 (SM98) alone for RWKV-Instant without RWKV-Curve.
- `RwkvRuntime::load_paired` accepts it as the instant side: a small model distinct from the release, with the same leak-free input rule, beside a full small release. It is rejected as the release side, beside itself, and beside Legacy or a leak-input model. No runtime code changed: the paired mode (`Paired`, `ARWKVPAIRSTATE1` states, `ARWKVPAIRCACHE1` cache, one store file) is the one of the [instant model for RWKV-Instant (SM93) integration](rwkv-sm93-2026-11-07.MD#runtime-design).
- Show-time inputs need no feature-builder change: the fork already builds the show-time intervals the model was trained on (as for the show-time retrain (SM92)); `rwkv_sm98_feature_builder_matches_show_time_intervals` checks the native feature builder against the trainer's interval inputs of all 6,543 queries and 7,860 answers of the package vectors (maximum error 7.5e−7).
- Python (`qt/aqt/rwkv_model.py`): `RWKV_SPECIALIZED_INSTANT_MODEL = "sm98"` (one constant to switch), `RWKV_INSTANT_ONLY_MODELS = ("sm57", "sm98")`, `RWKV_MODEL_FILES["sm98"]`, `single_model_for_profile`, and `runtime_models(..., single_model=...)`. The show-time retrain (SM92, `RWKV_INSTANT_MODEL`) and the instant-only small model (SM57, `RWKV_INSTANT_ONLY_MODEL`) stay bundled and selectable.

## States rebuild once

The replay key carries `instantModel`. Profiles that now run the pair (`sm72e25` + `sm98`) have a new key, so their RWKV state rebuilds from history once at the first open: profiles that used RWKV-Instant and RWKV-Curve with the default single model, and profiles that had the old toggle on (before: paired with `sm92`). The show-time instant-only model, stage 2 (SM98) alone has its own key (`model` `sm98`, no `instantModel`): profiles that use RWKV-Instant only (before: the show-time retrain (SM92) alone, or the pair in the first version of this integration) rebuild once, and a profile that switches between the pair and the show-time instant-only model, stage 2 (SM98) alone (a preset turns RWKV-Curve on or off) rebuilds once more. A pair's state never serves a single model, or the other way round, and states of different pairs are never mixed. Turning the opt-out on or off with both schedulers also rebuilds once, at the next profile open.

## Memory and CPU

Same architecture and state size as the instant-only small model (SM57), so the [SM93 measurements](rwkv-sm93-2026-11-07.MD#memory-and-cpu) hold (4,000 cards, 32,000 answers, INT4 card / INT8 note state): paired stream state 5.6 KB per card instead of 2.8 KB, warm-up 1.48 s instead of 0.91 s (both models replay in parallel, about 2× answer-replay CPU), queue scoring unchanged (93 ms against 95 ms), 1.35 MB more weights (f32). This is now the default cost of a profile that uses both RWKV-Instant and RWKV-Curve with the small model (SM63); the opt-out returns to one state, and RWKV-Instant without RWKV-Curve always runs one state (the show-time instant-only model, stage 2 (SM98) alone).
