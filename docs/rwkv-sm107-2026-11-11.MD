# The Big size on the show-time big model (SM107) — 2026-11-11

The **Big** model size (profile key `legacy`, Deck Options → RWKV → Advanced) now runs the show-time big model (SM91s2) instead of the big model (1 leak-free epoch). The user chose this on 2026-11-11. The show-time big model (SM91s2) is the big model (1 leak-free epoch) trained one more epoch with the same recipe (users 5000-10000, AdamW 3.5e-4 → 0, carried state, deleted-card inputs removed), the only change being show-time intervals: a query row's interval runs from the card's previous answer to the moment the card is shown, the time RWKV-Instant gives the model, instead of the review log's answer-to-answer interval. Same 2,762,884-parameter architecture and file format.

## Accuracy (upstream, show-time inputs)

anki-rwkv `artifacts/small-model/showtime/showtime-report.md` and branch `sm91s2`, `artifacts/small-model/sm91s2/sm91s2-decision.md`: 722 users of the 732-user held-out set, leak-free scoring (deleted cards: neighbour), INT8 weights and INT8 card / note state (w8+s8), show-time inputs (`--inputs e2s-query`), review-weighted LogLoss, paired user bootstrap (2,000 resamples, seed 0, 95% CI). The % are of the big model (1 leak-free epoch)'s show-time LogLoss of the same head (curve 0.29958, instant 0.277157); negative means the show-time big model (SM91s2) is better.

| Head | The show-time big model (SM91s2) | The big model (1 leak-free epoch) | Change [95% CI] | Users better / worse |
| --- | --- | --- | --- | --- |
| Curve | 0.299415 | 0.29958 | −0.06% [−0.12, +0.01] (tie) | 457 / 264 |
| Instant | 0.276183 | 0.277157 | **−0.35% [−0.46, −0.27]** | 584 / 137 |

On normal inputs (the review log's answer-to-answer intervals, which the fork does not give at a query) the added epoch costs a little: Curve +0.12% [+0.07, +0.18] and Instant +0.10% [+0.08, +0.12] of the big model (1 leak-free epoch)'s normal-input LogLoss. The show-time big model (SM91s2)'s own show-time cost is +0.03% Curve / +0.06% Instant, against +0.21% / +0.51% for the big model (1 leak-free epoch).

## What changed

- **Weights:** `qt/aqt/rwkv_inference/RWKV_trained_on_5000_10000.bin` (ARWKVWEIGHTS1, f32, 504 tensors, 11,082,637 bytes) is now SHA-256 `b53a89729d518c2db970833b7159904368fe9e882298e0f715f4d302f7cf4ed5` (was `0e07004d…`, the big model (1 leak-free epoch)). The developer checkpoint `RWKV_trained_on_5000_10000.pth` is the show-time big model (SM91s2)'s master weights, SHA-256 `67ee8e9b0d0169733242c40646e0d2e5637845a25775762002ffc4e6396f9590` (was `ac7f0d8a…`). Exported on CPU with the writer of 2026-11-10 (anki-rwkv branch `sm107-big-showtime`, `artifacts/small-model/sm107/sm107_export.py`); re-exporting the previous `.pth` with it reproduces the previous `.bin` byte for byte.
- **The previous file:** replaced, not kept, as on 2026-11-10 for Big. The preserved hidden values (the show-time retrain (SM92), the older small models) are separate profile keys with their own folders; Big has one key and one file, and no setting or test needs the previous weights. They stay in git history.
- **Unchanged:** the profile key `legacy`, the file name, `ModelKind::Legacy`, its leak-free input rule (inputs 13-15 zero on every row; the show-time big model (SM91s2) was trained without them too), and `load_paired` rejecting Legacy. The runtime already gives every model show-time intervals at a query, so no feature-path change is needed.
- **States rebuild once:** the state cache's model key carries the weights file's SHA-256, so a Big profile rebuilds its RWKV state from the retained review history once at the first open.
- **UI text:** the Big description in Deck Options says the model is trained on the time since the last review at the moment a card is shown.

## Verification

- **Native parity against PyTorch** (the same method and tolerance as the big model (1 leak-free epoch) on 2026-11-10: the trainer's PyTorch model on two users' full histories (users 4676 and 1745, 14,403 rows, 6,543 query rows, deleted cards: neighbour), instant recall, the four button probabilities, curve recall at the row's elapsed time and at six sweep times from the raw forgetting curve (the runtime ignores the big model's "ahead" logit residual), run through the fork's big engine with the leak-free rule, every value within 1e-5):
  - show-time inputs: maximum absolute error 1.5e−6 on all 14,403 rows;
  - normal inputs: maximum absolute error 1.5e−6 on all 14,403 rows;
  - bundled fixture (show-time, first 500 rows per user): 1.3e−6 (1,000 rows). For comparison, the big model (1 leak-free epoch) gave 1.6e−6 on its full normal-input vectors.
  - The vector script reproduces the previous fixture exactly when run on the previous `.pth` (features, IDs and skip flags identical, outputs equal to 0).
- **Show-time interval features:** the new `rwkv_legacy_feature_builder_matches_show_time_intervals` feeds the native feature builder each row's own interval and matches the published interval inputs (features 0..8) of every query and answer row: 6,543 query rows on the full vectors, maximum absolute error 7.5e−7 (fixture: 407 query rows, 7.3e−7).
- **Fixture:** `rslib/src/rwkv/testdata/legacy-vectors.json.gz` now holds the show-time big model (SM91s2)'s show-time vectors with each row's interval (anki-rwkv `artifacts/small-model/sm107/sm107_vectors.py ... e2s-query`, `sm107_fixture.py`). `ANKI_RWKV_LEGACY_VECTORS` points `rwkv_legacy_matches_published_vectors` at the full vectors, show-time or normal.
- **Tests run (Windows, CPU):** `cargo test -p anki --lib rwkv::` with default features (the big engine in `rwkv::alternate`) 262 passed, 31 ignored, and with `--no-default-features` 262 passed, 30 ignored; the three `legacy_tests` pass on the fixture and on both full vector sets. Python `qt/tests/test_rwkv_model.py`, `test_rwkv_inference_process.py` and `test_rwkv_scheduler.py`: 1,729 passed, 84 skipped (no built `_rsbridge.so` on Windows, no torch).
