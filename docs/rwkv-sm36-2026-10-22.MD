# SM36 Muon integration — 2026-10-22

SM36 is bundled alongside Legacy and SM40 and is the default when a profile has no supported saved model selection. Explicit Legacy and SM40 selections are preserved. Preferences → Review → RWKV offers all three choices; changing a choice takes effect after reopening the profile and rebuilding its local recurrent state. Storage precision is independent and unchanged: the default remains INT4 card matrices and INT8 note matrices, with f32 row scales, f16 shifts and f32 shared scopes.

## Upstream quality evidence

The [published SM36 release](https://github.com/JSchoreels/anki-rwkv/releases/tag/small-model-sm36-2026-10-22), observed after publication at 2026-10-21 23:51:28 UTC, reports a matched **729-user, 33.3-million-review** comparison. Both models use w8+s8: per-channel INT8 weights and INT8 card/note state. SM36 changes the final decay optimizer to Muon while retaining SM40's architecture and parameter count.

| SM36 minus SM40 | Review-weighted LogLoss change | 95% paired-user interval |
| --- | ---: | ---: |
| Curve | −0.00007 | −0.00028 to +0.00020 |
| Instant | −0.00016 | −0.00019 to −0.00013 |

Curve is statistically tied, while Instant improves slightly. SM36's absolute losses are **0.30426 Curve / 0.27915 Instant**, versus the big model's **0.30215 / 0.27733**, or **+0.70% / +0.66%**. The release also reports 464-user results consistent with the Instant improvement. At capture, one additional long user was still being scored; these figures describe the matched 729-user result, not a completed 730-user result.

The desktop retains f32 compute weights and its existing mixed state mode, so the upstream cohort is not a new many-user evaluation of the exact desktop configuration. No training or new multi-user evaluation was launched during integration. The matched native backup check below is additional evidence for the current desktop precision, with the scope of one collection.

## Matched native backup check

Both models replay the same **224,074 canonical retained answers** prepared from a temporary copy of `backup-2026-10-21-23.46.14.colpkg`. Only the weight file changes: both use f32 weights, INT4 card matrices, INT8 note matrices, the same feature construction and full history. No live profile database is opened or queried. Probabilities are recorded causally before the answer updates recurrent state. Curve uses the previous answer's curve at the current elapsed time; Instant uses the current pre-answer head.

| Head, 176,943 matched interday reviews | SM40 | SM36 | SM36 minus SM40 | Relative change |
| --- | ---: | ---: | ---: | ---: |
| Curve LogLoss | 0.46100351 | 0.46035114 | −0.00065238 | −0.1415% |
| Instant LogLoss | 0.45627509 | 0.45599996 | −0.00027513 | −0.0603% |

The all-repeated population of **210,097 reviews**, including same-day reviews, also improves: Curve **0.44680476 → 0.44622928** and Instant **0.44229566 → 0.44202287**. These are descriptive results from one collection, not independent user-level confidence estimates or a prospective scheduling/workload study. Individual predictions change with the new weights; the small aggregate improvement does not mean every prediction improves.

## Cache, runtime and UI behavior

The profile value is `rwkvModel = sm36`. Saved `legacy` and `sm40` values remain supported, while absent/unsupported values and new profiles select `sm36`. The active backend keeps its model and precision until the profile reopens. Replay identity includes the selected model name, and cache metadata includes the weight content hash, so SM40 state cannot satisfy operational SM36 cache validation even though the serialized architecture is compatible. Model switching does not rewrite collection data or stored scheduling dates. No state-store schema migration is needed.

The build copies SM36's f32 weights, architecture and manifest into the desktop package, and those built files match the verified source bytes. The optional INT8 weight container is retained for native reference verification; desktop compute weights remain f32. Existing low-level constructor defaults remain compatible with explicit SM40 callers; profile-driven construction passes the selected model explicitly.

Coverage includes all three models at all four state precisions for native checkpoint restoration and desktop checkpoint pruning, hypothetical answers, resident/snapshot prediction parity, workload simulation and actual answer/undo round trips. The real offscreen Qt selector test selects and saves Legacy, SM40 and SM36 using keyboard events, checks the independent precision selector, and verifies profile-reopen behavior and model-dependent replay identities.

The existing vector-conversion recipe retains its historical SM40 name because both exports have the same format. The [aggregate JSON](rwkv-sm36-2026-10-22.json) records package/model/input hashes, the frozen upstream quality figures, native vector errors and paired backup metrics. Private package, full vectors, copied-history input reference, prediction arrays and logs remain under `/private/tmp/rwkv-sm36-integration-2026-10-22/`. Zstd remains an independent, disabled checkpoint-storage experiment; none of this model's accuracy change is attributed to lossless compression.

The full suite is run with `TZ=UTC` because the pre-existing `ANKI_TEST_MODE` clock adjustment in `rslib/src/timestamp.rs` subtracts two hours from Rust timestamps between 02:00 and 04:00 local time, while Python review timestamps stay unshifted. In that window, Forget/reset tests can place a reset before the reviews it should discard. The same focused test was reproduced failing with `ANKI_TEST_MODE=1 TZ=Europe/Brussels` and passing with `ANKI_TEST_MODE=1 TZ=UTC`; production clock code and test assertions are unchanged.

Verification passed: the complete published NumPy checker, 184 optimized native RWKV tests with full SM36 vectors, the model/precision restore test with `--no-default-features`, native desktop checkpoint/undo/workload tests, the real Qt selector smoke test, and the complete `TZ=UTC just check` workflow. The integration is built into the development output; this task does not build an installer or change the active user's saved profile selection.
