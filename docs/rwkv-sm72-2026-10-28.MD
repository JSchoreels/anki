# Small model, leak-free (SM72) integration — 2026-10-28

The small model, leak-free (SM72) replaces SM56 as the default small model. Deck Options → RWKV → Advanced → **Use Smaller Model** selects SM72 when on and the Legacy big model when off. New profiles and profiles without a supported saved choice default to SM72. Existing explicit selections continue to load; a successful ordinary Deck Options save upgrades SM40, SM36, SM55 or SM56 to SM72. Discard, a failed save and parameter-only optimization preserve the saved selection. Reopen the profile to apply a saved change. Storage precision and f32 computation are unchanged.

## Why SM72 is the default

The fork already defaults to a small model and keeps Legacy as the opt-out. SM72 has the same architecture, size and state footprint as SM56, so the switch changes no resource trade-off: 331,511 parameters (8.3× fewer than the big model) and about 4.6 KB of card plus note state at INT8, against 25.7 KB for the big model. On identical leak-free inputs SM72 is better than SM56 on Instant on every held-out set (interval clear of zero) and better on Curve in the point estimate. Unlike SM56, it was never trained on the deleted-card signal that live Anki cannot provide.

## Leak-free input rule

In the training dataset, a card deleted before the export is missing from the cards table. Building features naively from that export sets the missing-note, missing-deck and missing-preset flags (inputs 13, 14 and 15) and gives all deleted cards one shared placeholder deck and preset. Live Anki never reviews a deleted card, so this is future information. SM72 was trained and scored without it:

1. Inputs 13, 14 and 15 are 0 on every row.
2. A card missing from the cards table keeps a note of its own (`314159265358979323 + card_id`).
3. It takes the deck of the existing card whose id is nearest (ties to the lower id), and that deck's preset, or the placeholder preset if the deck is unknown.

The runtime applies rule 1 whenever SM72 is selected (`ModelKind::leak_free_inputs`). `SrsModel::zero_unused_features` clears the three flags, next to the existing feature-22 rule, in all four places where features enter the network: the per-review and bulk-replay feature MLP, the scalar query path and the batched query path. Other models, Legacy included, keep their feature path unchanged.

Rules 2 and 3 never apply in the fork. Canonical history joins the review log to `cards` in both the native and the fallback desktop query, so a deleted card's reviews are not replayed ([Deleted Cards' Reviews](rwkv.MD#deleted-cards-reviews)), and live reviews always carry the card's real note, deck and preset. A runtime input that still lacks an identity keeps the existing placeholder entities with the flags at zero, the fallback the release documents for a runtime without a neighbour card.

## Verification

The RWKV module tests were compiled and run on Windows x86-64 (CPU only) in a standalone Cargo harness that includes `rslib/src/rwkv/` unchanged and provides stand-ins for the three crate items it imports (`CardType`, `relative_overdueness` and the review-order and deck protobuf types); the full desktop build was not available on that machine.

- Default features (small primary engine): 177 passed, 30 ignored, 4 failed. Without default features (Legacy primary engine): 177 passed, 29 ignored, 4 failed.
- The four failures are the bit-exactness checks of the experimental fused packed INT4 kernels (`fused_packed::tests`, in both engines). They fail identically on the unmodified `origin/main` in the same harness, are test-only benchmark code, and are unrelated to this change.
- New tests: `rwkv_sm72_matches_published_vectors`; `rwkv_sm72_ignores_missing_id_flags_in_every_inference_path`, which shows that setting inputs 13–15 changes none of SM72's outputs in the review, scalar query and batched query paths, while the same weights without the rule do change; and `rwkv_runtime_feeds_only_sm72_leak_free_inputs`, which shows that selecting SM72 changes predictions only for histories with missing identities and leaves SM56 untouched. `rwkv_runtime_restores_each_model_at_each_precision` and `rwkv_sm40_spec_matches_compiled_architecture` now include SM72.
- Desktop and browser tests were updated in the existing style (model defaults, save migration, bundled file paths, embedded backend configuration) but could not be run on this machine; the remote CI runs them.
- `rustfmt --edition 2021` reports no changes for the edited Rust sources. Clippy reports no warnings in the changed code.

## Not done

- No matched backup or own-collection comparison for SM72; the release did not measure the own collection either.
- INT8 card/note state has no golden vectors upstream; the desktop's default mixed INT4-card/INT8-note storage for SM72 is covered by the native restore test but not by accuracy vectors.
- The desktop feature builder's entity codes and calendar phases differ from the training scorer's; the effect on SM72 accuracy was not measured upstream.
