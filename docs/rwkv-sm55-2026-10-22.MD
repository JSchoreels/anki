# SM55 integration — 2026-10-22

SM55 is bundled alongside Legacy, SM40 and SM36 Muon. It is the default for new profiles and profiles without a supported saved model selection; all explicitly saved supported choices remain unchanged. Select SM55 in Preferences → Review → RWKV and reopen the profile to switch an existing saved choice. Computation still uses f32 weights, and default storage still uses INT4 card matrices, INT8 note matrices, f32 row scales, f16 shifts and f32 shared scopes. Zstd remains disabled.

This integration launches neither training nor a new multi-user evaluation. Upstream w8+s8 results are not a many-user validation of the desktop's exact f32-weight, mixed-state mode.

The upstream many-user gain motivates offering SM55 as the default, while preserving existing explicit choices and the SM36 option.

Predictions are recorded causally before each answer updates state. Curve uses the previous answer's curve evaluated at the current elapsed time; Instant uses the current pre-answer head. The first review of each card is excluded from scoring, and both slices use the same existing eligibility flag. LogLoss clips probabilities to [1e−6, 1−1e−6], matching the existing model comparison tool.

The subsequent [four-model comparison](rwkv-four-model-quality-2026-10-22.MD) adds the big model on exactly this input and precision: interday Curve **0.46095616**, Instant **0.45598502**. ## Model selection, cache and runtime

The supported profile values are `legacy`, `sm40`, `sm36` and `sm55`; missing/unsupported values and newly created profiles select `sm55`. The active session keeps its current model and precision until reopening. Replay identity includes the model selection, and cache metadata includes the weight content hash, so an SM36 cache cannot satisfy operational SM55 validation despite sharing the state format. Switching reconstructs state from retained history without rewriting collection data or stored due dates; no cache schema migration is needed.

All three small checkpoints share the existing native small architecture. Runtime dispatch supports all four models in both Cargo feature configurations while compiling two engine specializations. Existing low-level SM40 constructor defaults and the `rwkv-sm40` offline architecture feature retain their compatibility behavior. The desktop build contains the verified f32 weights, architecture and manifest; built asset bytes match the imported source files. The optional INT8 container is kept for reference tests, not selected for production computation. The live profile and running application are unchanged; this task builds development output, not an installer.
