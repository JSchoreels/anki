# Big pair in the fork (SM109) — 2026-11-12

The **Big** model size (profile key `legacy`, Deck Options → RWKV → Advanced) now pairs its two-head model with its own RWKV-Instant model, the way **Small** already pairs its models:

| Presets use | Big (`legacy`) | Small (`sm72e25`), for comparison |
| --- | --- | --- |
| RWKV-Instant and RWKV-Curve (default) | the show-time big model (SM91s2) for the curve, intervals and the 90% stability, beside the show-time instant-only big model (SM99) for RWKV-Instant's recall and button probabilities | the default small model (SM63) beside the Small Instant-Only model (SM98) |
| RWKV-Instant and RWKV-Curve, one-model opt-out | the show-time big model (SM91s2) alone | the show-time retrain (SM92) alone |
| RWKV-Instant without RWKV-Curve (with or without the opt-out) | the show-time instant-only big model (SM99) alone, an instant-only runtime (no curve, intervals, 90% stability, answer time or workload simulation; due dates from the FSRS fallback) | the Small Instant-Only model (SM98) alone |
| RWKV-Curve only, or neither | the show-time big model (SM91s2) alone | the default small model (SM63) alone |

Tiny is unchanged. Before this change Big ran the show-time big model (SM91s2) alone in every case.

## What changed

- **Weights:** `qt/aqt/rwkv_inference/sm99/weights.f32.bin`, the same format as the Big file (ARWKVWEIGHTS1, f32, 504 tensors, 11,082,637 bytes), SHA-256 `682ba1ff207c51af7de5e2abeb25593362aa706b292cbcc338a1591fad0d935c`, exported on CPU with the writer of the Big file (anki-rwkv branch `sm107-big-showtime`, `artifacts/small-model/sm107/sm107_export.py`) from the final checkpoint (epoch 2, SHA-256 `c49e45d6…`). It is byte-identical to `weights.f32.bin` of the family package `artifacts/models/sm99` (anki-rwkv branch `big-package`, commit 9dc96c91), whose `manifest.json` and `architecture.json` sit beside it. The build copies the folder like the small models' folders; `.gitattributes` keeps its bytes.
- **Runtime (`rslib/src/rwkv/runtime.rs`):** `ModelKind::Sm99` (key `sm99`): instant-only, leak-free, big architecture. `RwkvRuntime::load_paired` now accepts two distinct models of one architecture: two small models (as before, small-model feature only) or the two big models (`legacy` beside `sm99`). A big model never pairs with a small one, and `sm99` is never the release side. `PairedRuntime` is generic over the engine: with the default features the Big pair is `AlternatePaired` and SM99 alone is `AlternateInstantOnly` (the big engine is `rwkv::alternate`); with `--no-default-features` the big engine is the primary one and they use `Paired` / `InstantOnly`. Every code path is the Small pair's (the `dispatch!` macro expands the same paired and instant-only bodies for both engines): both models replay every answer in parallel; RWKV-Instant's recall and buttons come from SM99, the curve, intervals and 90% stability from SM91s2; snapshots, the delta store, stashes and undo hold both states; workload simulation runs on SM91s2. Neither big model has an answer-time head.
- **Profile mapping (`qt/aqt/rwkv_model.py`):** `RWKV_BIG_INSTANT_MODEL = "sm99"` in `RWKV_CHOICE_INSTANT_MODELS` and `RWKV_INSTANT_ONLY_MODELS`; `RWKV_CHOICE_SINGLE_MODELS` gives the opt-out's one model per choice (Big: the show-time big model (SM91s2); Small and Tiny keep the show-time retrain (SM92)).
- **Deck Options:** the one-model switch now shows for Big too; the Big description and the switch's explanation say so.

## Memory (card + note, exact stored state)

`rwkv_big_pair_stores_two_big_states_per_card_and_note`: a pair stores, per stream, a 19-byte pair header plus one state of each big model (both models have 3 card layers and 2 note layers, d_model 128, 4 heads of 32).

| State precision | Big alone (SM91s2 or SM99): card + note | Big pair: card + note | Small pair, for comparison |
| --- | --- | --- | --- |
| int4 cards + int8 notes (default) | 9,271 + 10,283 = 19,554 B | 18,561 + 20,585 = **39,146 B** | 7,098 B |
| int8 | 15,415 + 10,283 = 25,698 B | 30,849 + 20,585 = 51,434 B | |
| f32 | 52,278 + 34,858 = 87,136 B | 104,575 + 69,735 = 174,310 B | |

So with both schedulers in use, Big takes twice its previous card and note memory (plus 38 bytes) and replays every answer on both big models; the opt-out returns to one model. Deck, preset and user states are per deck, preset and collection.

## Switching sizes rebuilds state

The replay key holds the model key and, for a pair, `instantModel`, and the state cache key holds the weights' SHA-256, so switching between Big's pair, Big alone, SM99 alone and the other sizes' layouts rebuilds the state once from the retained review history and never reuses another layout's state (`test_paired_runtime_gets_its_own_replay_identity`: 11 distinct keys). The runtime also refuses a saved runtime cache of another architecture or pairing and an undo state of another engine or pairing (`rwkv_switching_sizes_never_reuses_another_layout_state`), and a pair never reads a single model's snapshot, cache or delta store or the reverse (`rwkv_big_pair_state_round_trips`). A preset turning on RWKV-Curve beside SM99 alone swaps the runtime at once, as for SM98 and SM101.
