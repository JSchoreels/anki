# The Tiny one-model choice and Tiny for RWKV-Instant alone (SM112) — 2026-11-13

Two changes the user decided on 2026-11-12:

1. **Tiny's one-model choice** (Tiny, both schedulers, **Use one model for RWKV** on) runs the Tiny two-head model (SM106) alone instead of the show-time retrain (SM92). Tiny's default pair is unchanged: the default small model (SM63) for the curve beside the Tiny Instant-Only model (SM101), because the default small model (SM63) is more accurate on the curve than the Tiny two-head model (SM106) (the Tiny two-head model (SM106) minus the default small model (SM63): curve +0.088% [+0.001, +0.210]).
2. **RWKV-Instant alone** (no preset uses RWKV-Curve) runs the Tiny Instant-Only model (SM101) for Small too, instead of the Small Instant-Only model (SM98, the show-time instant-only model, stage 2). The user's words: "if the user only wants instant predictions, we can use Tiny directly". It is the default behaviour of RWKV-Instant alone, so it does not depend on the size setting: Small and Tiny both run the Tiny Instant-Only model (SM101) there. Big keeps the show-time instant-only big model (SM99) alone, since Big is an explicit choice.

## What each size runs

Presets "use RWKV-Curve" when RWKV-Curve is their scheduler or RWKV-Instant's **Fallback : Due-Date Calculator** (both set `rwkv_review_enabled`). Changes against the previous build in bold.

| Presets use | Big (`legacy`) | Small (`sm72e25`, default) | Tiny (`tiny`) |
| --- | --- | --- | --- |
| RWKV-Instant and RWKV-Curve (default) | the show-time big model (SM91s2) for the curve, intervals and S90, beside the show-time instant-only big model (SM99) for RWKV-Instant | the default small model (SM63) beside the Small Instant-Only model (SM98) | the default small model (SM63) beside the Tiny Instant-Only model (SM101) |
| RWKV-Instant and RWKV-Curve, one-model opt-out on | the show-time big model (SM91s2) alone | the show-time retrain (SM92) alone | **the Tiny two-head model (SM106) alone** (was the show-time retrain (SM92)) |
| RWKV-Instant without RWKV-Curve (opt-out ignored) | the show-time instant-only big model (SM99) alone | **the Tiny Instant-Only model (SM101) alone** (was the Small Instant-Only model (SM98)) | the Tiny Instant-Only model (SM101) alone |
| RWKV-Curve only, or neither | the show-time big model (SM91s2) alone | the default small model (SM63) alone | the default small model (SM63) alone |

A pair gives RWKV-Instant's recall and button probabilities from its instant model and the curve, intervals, S90 and answer time from its curve model. An instant-only model alone (the Tiny Instant-Only model (SM101), the show-time instant-only big model (SM99)) has no curve, intervals, S90, answer time or workload simulation: due dates and memory states come from the FSRS fallback. The Tiny two-head model (SM106) alone is a full model (curve, intervals, S90, instant recall and buttons) without an answer-time head, so with Tiny's one-model choice Card Info shows no RWKV answer-time rows (as with Big). Profiles that hold the show-time retrain (SM92) as a preserved choice, or an older small model until their next Deck Options save, run that one model alone in every case (unchanged).

**Reading of the size picker.** The size stays the profile value `rwkvModel`; nothing in the stored settings changes. "RWKV-Instant alone uses Tiny" is implemented in `runtime_models()` as the default for every size with an RWKV-Instant model (`RWKV_INSTANT_ALONE_MODEL`, the Tiny Instant-Only model (SM101)), with Big as the one exception (`RWKV_CHOICE_INSTANT_ALONE_MODELS`). It is not done by changing Small's RWKV-Instant model (`RWKV_CHOICE_INSTANT_MODELS`), which would also have moved Small's pair to the default small model (SM63) beside the Tiny Instant-Only model (SM101). The preserved choice of the show-time retrain (SM92) and the older small keys are explicit one-model choices and keep running alone, as Big keeps its own models. The Deck Options texts say this without model IDs: Small's description says RWKV-Instant alone runs on Tiny's smaller RWKV-Instant model, Tiny's that its one-model setting runs one tiny model for both (no answer-time estimate), and the opt-out's explanation names Tiny's one model and says it is slightly less accurate on RWKV-Curve.

## Switching modes: rebuild or reuse

The replay key holds the runtime's `model` and, for a pair, `instantModel`; the model cache key holds the main weights' SHA-256 (the Tiny Instant-Only model (SM101) and the Tiny two-head model (SM106) have the same file name and size: only the hash tells them apart, and it does). Tests in `qt/tests/test_rwkv_model.py`:

- `test_switching_sizes_and_schedulers_rebuilds_or_reuses_state`: over all 3 sizes × 6 scheduler / opt-out cases (18 combinations), two combinations share a replay key exactly when they run the same models. So Small ↔ Tiny with RWKV-Instant alone (both the Tiny Instant-Only model (SM101)) and with RWKV-Curve only or neither (both the default small model (SM63)) keep their state; Small ↔ Tiny with both schedulers (pair or one model) and every change between a pair, a one-model runtime and an instant model alone rebuild once.
- `test_states_built_on_the_previous_model_rebuild_once`: a Small RWKV-Instant-only profile whose state was built on the Small Instant-Only model (SM98) (with or without the opt-out), and a Tiny opt-out profile whose state was built on the show-time retrain (SM92). The new build's runtime models are the Tiny Instant-Only model (SM101) and the Tiny two-head model (SM106); the saved replay key and model hash no longer match (`_rwkv_state_cache_collection_unchanged` and `_rwkv_state_cache_model_usable` refuse them), so the state is rebuilt once from the review history. The rebuilt state's identity is stable, so the next open reuses it.
- `test_tiny_models_of_equal_size_never_share_a_model_key`; `test_paired_runtime_gets_its_own_replay_identity` (12 distinct keys, the Tiny two-head model (SM106) alone added); `test_small_and_tiny_instant_alone_reopen_once_a_preset_uses_curve` (the Tiny Instant-Only model (SM101) alone under Small or Tiny is dropped at once when a preset turns RWKV-Curve on; the next runtime is the size's pair, or its one model with the opt-out).

The native runtime does not itself tell two small models' states apart: a warm-up snapshot of a two-card-layer model restores into a one-card-layer model and the reverse. This was already so between Small and Tiny since the model sizes (SM104), and between any two small models before; the replay key and the model hash above are what keep states apart.
