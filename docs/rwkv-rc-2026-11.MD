# RWKV release candidate 2026-11 (branch `rc-2026-11`)

Branch `rc-2026-11` collects the fork side of the next RWKV family release. It is not
merged into `main`; no release build, tag or package was made from it.

## What the branch holds

1. **The compact state format** (branch `rc-state-int8`,
   [report](rwkv-rc-state-format-2026-11-21.MD)): int8 card rows and compact notes
   (`compact_cards_int8`) for every size, state cache version 14, no state-decode
   panics, `WEIGHTS-NOTICE.md`.
2. **Answer-time heads for the whole family** (branch `rwkv-time-heads-family`,
   [report](rwkv-time-heads-2026-11-16.MD)): heads of the time heads for the family
   (SM117) and of the time heads for the new candidates (SM119), and the longer
   Instant-Only models (SM113, SM115).
3. **The release candidate's models** (this report): Small's two-head model becomes
   the show-time two-head cool-down for Small (SM118), and Tiny becomes the
   six-layer Tiny (SM130), both chains (user decision 2026-11-21).

| Size | Two-head model (key, master sha256) | Instant-Only model (key, master sha256) |
| --- | --- | --- |
| Big | the show-time big model (SM91s2) (`legacy`, `67ee8e9b`), unchanged | the show-time instant-only big model (SM99) (`sm99`, `c49e45d6`), unchanged |
| Small | the show-time two-head cool-down for Small (SM118) (`sm118`, `b4fe1175`), head from SM119 | the longer Small Instant-Only model (SM113) (`sm113`, `e4574e2a`), head from SM119 |
| Tiny | the six-layer Tiny two-head model (SM130) (`sm130th`, `48a5e724`), head from SM138 | the six-layer Tiny Instant-Only model (SM130) (`sm130io`, `23f03728`), head from SM138 |

The models they replace stay bundled and unused by any size: the show-time retrain
(SM92, still a profile value of its own), the Tiny two-head model (SM106) and the
longer cool-down for Tiny (SM115) (and the older SM98 / SM101). Each size runs only
its own models; there is no cross-size fallback.

## The six-layer Tiny in the native engine

The fork compiles the dimensions of each engine (`D_MODEL`, `HEAD_DIM`, `HEADS`,
`HEAD_SIZE`, `MODULE_LAYERS`, the channel-mixer layout) and already loaded the
one-card-layer Tiny through a runtime *layer plan* (`LayerPlan`: per-stream layer
counts and the interleaved step order). The six-layer Tiny (arch `w64-c1-d2p1u1`:
card 1, deck 2, note 1, preset 1, user 1 layers; steps `(0,0) (1,0) (2,0) (3,0) (4,0)
(1,1)`, an exact subsequence of Tiny's; channel mixers card 0, deck 0, note 0 as
Tiny) fits that mechanism without touching the compiled constants:

- `architecture.rs`: `SIX_LAYER_PLAN` and `SMALL_LAYER_PLANS` (engine, tiny,
  six-layer).
- `engine.rs`: `layer_plan_for` counts each stream's layers in the weights and picks
  the plan with those counts (any other layout keeps the engine's plan and fails to
  load as before; the big engine always uses its own). The answer-time head's width
  is computed from the plan (`answer_time_inputs`: (layer rounds + 1) x 64 + 128 +
  26 = 474 for four rounds, 346 for the six-layer plan's two); a head is loaded with
  the width it holds and refused beside a model of another width.
- `runtime.rs`: `ModelKind::Sm118`, `Sm130Th` (`sm130th`), `Sm130Io` (`sm130io`,
  instant-only); both SM130 kinds and SM118 are leak-free. Each small key names its
  stream layer counts (`module_layers`), and weights with other counts are refused
  for it (before: only the card layer count was checked, which could not tell Tiny
  from the six-layer Tiny).
- Nothing else depends on the layer counts: the bulk and wavefront replay, queries,
  checkpoints and spills already iterate the plan's steps.

State per card and per note is Tiny's (1,315 B each at `compact_cards_int8`; pair
5,298 B per card + note); the cut streams (deck, preset, user) are not per card. The
f32 / int8 weight files are 752,409 / 238,585 B (Tiny 1,270,749 / 409,483 B).

## Weights and export path

The packages were made exactly as those of SM113 / SM115 (the `time-heads-package`
worktree's path), in a separate anki-rwkv worktree `wt/fork-rc-export` (detached at
the SM138 commit `75266753`, which has the `w64-c1-d2p1u1` preset and the SM138
model table; nothing was written into the experiment worktrees):

   verified master (sha256 above): `weights.f32.bin`, `weights.int8.bin`,
   `architecture.json`, `manifest.json`, parity vs the NumPy reference (PASS, max
   |dp| <= 1.4e-6 for fp32 and w8).
2. Test vectors on the SYNTHETIC users 900001 / 900002
   (`scripts/synthetic_testvector_users.py`, fixed seed, no dataset rows):
   `testvectors/make_testvectors.py` + `check_testvectors.py` PASS (tolerance 1e-5).
3. `artifacts/small-model/fork-rc/sm130_fork_package.py`: neutral paths, manifest
   `model`, `evaluation` (from the decision files), `use`, `inputs`, `testvectors`,
   files re-hashed.
4. `artifacts/small-model/fork-rc/time_heads_package.py` (the SM119 packager plus
   `sm118`, `sm130th`, `sm130io` and the 346-input layout): trunk check (the head's
   frozen trunk equals the master and the fork's weights tensor for tensor), head
   files `time_head.{f32,int8}.bin` + `time_head.json` (format 2), and the synthetic
   time fixture.
5. Fixtures for the fork: `qt/tools/rwkv_sm40_vectors.py --limit 500 --intervals`
   into `rslib/src/rwkv/testdata/{sm118,sm130th,sm130io}-vectors.json.gz` and
   `...-time-vectors.json.gz` (first 500 rows per synthetic user).

The fork bundles the weights (it downloads nothing): `qt/aqt/rwkv_inference/<key>/`
holds `weights.f32.bin` (shipped), `weights.int8.bin` (tests), `architecture.json`,
`manifest.json`, `time_head.*`. The build copies `WEIGHTS-NOTICE.md` into
`_aqt/rwkv_inference/` and into every model folder there.

## Answer time

The answer time is the whole time on the card, front and back together: from the
question shown to the grade press, capped at the preset's maximum answer seconds (the
"Show answer" moment is not stored). "Recall within S s" means recalled (Hard, Good
or Easy) and answered within S s, reading the back included. Every model a size runs
has its own head; a pair answers from its Instant-Only model's head. The six-layer
Tiny heads (SM138) pass their gate (time LogLoss 1.9931 two-head / 1.9877
Instant-Only vs 2.3849 for the user's running median); they are 1.3-1.6% worse than
the four-round Tiny heads, a shallower trunk.
